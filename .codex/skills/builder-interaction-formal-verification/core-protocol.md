# Builder core protocol: hydration, save, reconcile, preview

The four-request core flow: load Builder state, save an edit, reconcile (compile + receipt), preview the receipt. This map records the actual callers, identities, and awaited boundaries; witnesses are listed at the bottom and gaps stay gaps.

## Identities and ordering in force

- Save carries `commandId`, `semanticsVersion`, `snapshotToken`, `expectedDraftVersion`, `expectedDraftDigest` and `X-Request-ID`; save is a compare-and-swap against the draft head. SaveDraft commits head move, history revision, and validation in one store transaction (`internal/explorer/service.go` `SaveDraft`).
- Server reconcile validates `draftVersion`/`draftDigest` once at entry against the persisted head (`internal/explorer/lifecycle/authoring.go:552-558`: `owner.DraftVersion != request.DraftVersion || owner.DraftDigest != request.DraftDigest` → `DRAFT_CONFLICT`), then captures that decoded workspace for compile and response. No second head read re-derives the result (witnessed by fault F1).
- Preview admits a retained receipt from its own identity chain: route match, capability-snapshot authorization, output membership, emitted-column contract (`internal/explorer/lifecycle/preview.go:28-44`). There is deliberately no "receipt equals current head" requirement — historical receipts keep executing after the head advances (witnessed by fault F2); the client binds rows to identity instead.
- Preview result must echo the request-side identity or is discarded: `value.receiptId !== activeReceipt.receiptId || value.outputId !== activeRequest.outputId` → drop (`BuilderWorkspace.tsx:2760-2764`), under `previewGeneration` monotonic guards (`BuilderWorkspace.tsx:643, 2736-2742`).
- Commands execute FIFO through `commandQueue` with `pauseAndDrain` before draining (`BuilderWorkspace.tsx:652, 822-826, 930`); reconcile retry branches `maxAttempts = 3` and `maxStaleRefreshes = 2` are independent counters inside the reconcile flow (`BuilderWorkspace.tsx:2597-2680`), so stale-driven reloads and transport retries interleave through the queue rather than racing it.
- Stale in-flight reads are epoch-gated: request epoch/controller checks (`react.tsx:77-108`), workspace-attachment gate (`BuilderWorkspace.tsx:461-463, 2009, 2597, 2609`), row-change epoch (`BuilderWorkspace.tsx:2140`).
