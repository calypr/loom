# Builder reliability goal

Make Loom Explorer Builder dataframe-building workflows reliable against the real local CDA dataset, using the active queue in `docs/BUILDER_WORKLIST.tsv` and the batch plan in `docs/BUILDER_WORKLIST.md`. Preserve existing worktrees, staged patches, accepted scoped evidence and the complete feature inventory.

Inventory visible Builder features and distinct transitions that change row identity, multiplicity, available columns, source bindings or starting collections. Prioritize starting-collection repair, repeated/composed operations and upstream edits. Expand by new behavior classes, not every permutation. Keep exploratory waves to at most ten new sequences; known failures and required lifecycle checks remain in scope.

Execute each bounded batch in three explicit phases:

1. Implementation: complete all ready independent implementations before full review or browser QA. Use at most three teams, each with up to three Luna xhigh workers in separate worktrees and one Luna max lead. Give each issue and file one owner. Workers reproduce from retained evidence, add executable `.mjs` regressions, fix root causes and run cheap faithful focused checks. Reuse existing native workflows and oracles. Separate missing evidence, harness defects, product defects, performance failures and fixture gaps. Do not invent product changes for a metadata gap. Record dependencies and unavailable witnesses explicitly; they do not hold ready work indefinitely.
2. Consolidated review: after ready implementation finishes, Luna max leads review their complete team batches and own correction iterations. Foreground Sol reviews the integrated submissions and accepts or rejects them. Leads integrate accepted patches serially into the agreed integration branch, preserving unrelated dirty work. Verify consequential conflict resolutions. Do not interrupt implementation with foreground review of every small driver correction, and do not claim a lifecycle is complete from focused tests.
3. Batch QA: freeze the reviewed integrated source once and run complete native Playwright Test cases concurrently where QA data, Explorers, artifact directories, publication identities and setup/cleanup effects are demonstrably independent. Serialize only cases sharing mutable state and isolated runtime probes. Retain source fingerprints, API identity, first-failure diagnostics and terminal request evidence. Treat concurrent latency as provisional and confirm timing failures serially. Gather failures into the next implementation batch, extract the cheapest faithful regressions and rerun affected full cases after reviewed integration. Do not repeat unchanged passing cases without a concrete changed behavior or missing proof.

For every feature and transition, prove the user path from selection through the actual settled table rows using independent fixture or CDA source expectations. Verify native controls, preview correctness, Cancel/Apply where applicable, edit, removal/restoration, persistence after reload and action-to-render latency within five seconds. Retain the existing explicitly approved ten-second exceptions only for full-population root quantity Pivot and related text-only quantity Pivot. Preserve membership, authorization, project and generation semantics, row identity, multiplicity, null/missing/empty distinctions and source bindings.

Investigate unavailable controls and backend refusals rather than hiding supported functionality or adding unnecessary clicks. If an operation cannot work for the scoped data state, establish the specific reason and make its availability understandable before the user encounters a late failure. Keep fixture absence scoped to the actual bounded search; do not infer global absence. Treat performance separately from correctness and profile structural cost when measured local corrections fail.

Maintain one actionable worklist and an honest coverage matrix with exact case contracts, owners, next actions, dependency and parallel-state constraints, commands, evidence and source applicability. Keep historical proof separate from current-source proof and basic fixture coverage separate from CDA acceptance. Reconcile metadata without unnecessary browser reruns. Infrastructure changes must address a demonstrated blocker or misleading result, not become a separate endless optimization project.

Completion requires every inventoried feature to have a verified lifecycle, each distinct transition class to be covered, and every reproduced failure to be fixed with a passing regression and applicable browser evidence, or explicitly reported with the specific unresolved product decision or external blocker. Review the full goal inventory before declaring completion. Worker activity, commits, claimed passes, partial assertions and a green selected suite do not establish completion.
