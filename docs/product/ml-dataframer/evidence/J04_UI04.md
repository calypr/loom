# J04 UI04 browser verification

`make verify-j04` loads the version 2 contract in `testdata/devloop-fixture/j04-contract.fixture.json` and its J04-only `j04-records.ndjson.fixture` source. The command partitions that source into resource-valid `Observation.ndjson` and `Patient.ndjson` uploads, so these records do not enter other verifier projects.

The fixture defines separate row scopes. Builder starts with one row per Observation and authors five base columns. The operator oracle uses an explicit one-Patient population containing `Patient/j04-patient-001`. It expects COUNT 3, EXISTS true, MIN 0, MAX 180, MEAN 120, and SUM 360 after converting 1.8 m to 180 cm. The Jan 10 Observation is outside the Jan 1 inclusive through Jan 3 exclusive window. Two Jan 2 values tie, and source ID ordering selects `j04-measure-002`.

The unsupported furlong input belongs to a separate refused proposal for `Patient/j04-patient-002`. The contract expects `UNIT_IDENTITY_UNKNOWN` and no apply. It does not expect a successful aggregate row with null results for that Patient.

The pivot uses Observation category codes with logical type string and a numeric `valueQuantity.value` column normalized to cm. It groups by `subject.reference` and `status`, sums duplicate alpha inputs, emits null for a missing beta category, and records unlisted source records. The pivot phase authors `subject.reference` and `code.coding[].code` in addition to the base columns. The repeated schema path is projected through the compiler-owned scalar form; the browser never substitutes an array index. The Quantity system/code siblings remain compiler inputs to the unit policy rather than becoming user-visible dataframe columns. Separate live FHIR evidence keeps missing, recorded null, false, zero, and a whitespace-only string distinct without mixing those values into the numeric pivot column. The lower-level typed-evidence oracle separately retains the empty JSON string, which FHIR ingestion rejects as an invalid primitive.

The pivot output includes `j04_alpha_plus_beta`. It expects 7.5 for Patient 001 and null for Patient 002 under `PROPAGATE_NULL`. A separate Patient aggregate phase expects `sum + count = 363`, division by zero to produce null, and a later derived reference to produce 364. The fixture also pins exact contributors, exclusions, missing-category evidence, unchanged `status = final`, receipt and reload behavior, a stale apply response of 409, and agreement between Preview, Viewer, and a JSONL artifact with native JSON types.

The aggregate oracle deliberately uses a separate Patient row scope from the Observation reshape output. The exact aggregate population is `Patient/j04-patient-001`; the live Builder attempt records the Starting collection panel and reports this operator journey as not proven when no immutable selection revision for that identity is available. Builder can attach a supplied selection through a visible route, but this fixture does not seed one and the verifier does not create one through an API.

The Observation journey uses only visible Builder controls. It authors base, pivot-source, scalar-presence, and recoding columns, then opens Table shape settings with `[data-testid="ui04-open-table-shape-settings"]`. Once the route controller renders the dialog/editor, the driver selects grouped pivot, discovers and freezes the exact alpha/beta categories, configures SUM/NULL/EXCLUDE policies and the derived alpha-plus-beta output, previews a receipt-backed comparison, checks that preview/cancel leave the saved workspace unchanged, reproposes, and confirms with `[data-testid="ui04-confirm-table-shape"]`. Contributor, exclusion, information-loss, proposal receipt, and network response evidence are captured without using API authoring.

On the current integration source, the first expected route-controller boundary is `[data-testid="ui04-open-table-shape-settings"]`; if it is absent, the run stops precisely there and marks later work not proven. The driver includes the follow-on component selectors so a live run will exercise them as soon as the production controller is present. Preview, Viewer, publish/reload, stale-proposal 409, and downloaded typed-artifact agreement remain explicitly unproven until the live controller and cross-surface sequence run successfully; no API-authored proof is substituted.

Each run writes `report.json`, before/after workspace snapshots, Builder DOM captures, a failure screenshot when Chrome can capture one, a redacted network summary, and `J04-evidence.md` under `.artifacts/loom-dev/<session>/<run-id>/`. The run-specific evidence note records the first missing action and its directory.
