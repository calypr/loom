# J04 UI04 browser verification

`make verify-j04` loads the version 2 contract in `testdata/devloop-fixture/j04-contract.fixture.json` and the isolated `j04-records.ndjson.fixture`. The driver partitions those records into valid Patient and Observation uploads, creates fresh project state, and performs authoring only through visible Builder controls.

The fixture deliberately separates two row scopes:

- The Patient operator journey attaches an explicit one-Patient starting collection. It configures a bounded contributor window, converts `1.8 m` to `180 cm`, and proves COUNT 3, EXISTS true, MIN 0, MAX 180, MEAN 120, and SUM 360. The Jan 10 record is excluded. Equal Jan 2 timestamps are resolved deterministically by FHIR resource identity. An unsupported `furlong` proposal is refused with `UNIT_IDENTITY_UNKNOWN` and is not applied.
- The Observation table proves scalar presence, recorded FHIR absence, exact category recoding, grouped pivot, and a derived column. It groups by `subject.reference` and `status`, sums duplicate `alpha` cells, emits null for a missing `beta`, excludes unlisted categories, and computes `j04_alpha_plus_beta` under `PROPAGATE_NULL`. No unit normalization is configured for this pivot, so the compiler correctly emits no result-unit metadata.

The source-presence checks retain false, integer zero, and whitespace as values, distinguish a missing source property through CellTrace, and use `dataAbsentReason=unknown` for valid FHIR recorded absence. Preview is rectangular, so missing and recorded absence both render as null cells; CellTrace supplies their different source evidence.

The table-shape flow discovers and freezes exact `alpha` and `beta` categories, configures SUM/NULL/EXCLUDE policies, and creates `j04_alpha_plus_beta`. Proposal Preview reports bounded contributors, complete exclusions, and information-loss reasons. Cancel leaves the workspace byte-identical. Apply uses a fresh receipt, and a later attempt to apply the original proposal receives HTTP 409 without mutating the saved draft. Reload preserves the table shape, stable column identities, and literal grouped rows.
