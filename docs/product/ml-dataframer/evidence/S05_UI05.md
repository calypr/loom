# S05 / UI05 verification evidence

Run `make verify-j05` against the isolated development stack. The command creates a fresh verification project and records a JSON report, DOM snapshots, and the downloaded ZIP under that project's `.artifacts/loom-dev` directory.

The browser journey starts with an empty bootstrap Explorer. It opens `Review dataset`, verifies the deterministic no-table blocker, and follows its action to the owning `first-table-name` control. It then seeds the existing Patient fixture into that same Explorer, reloads Builder, previews the table, reviews the saved output, publishes it, opens and reloads Viewer, explains a family cell, filters gender to `female`, and downloads the complete authorized dataset.

The downloaded archive is checked as a manifest-v2 package. The verifier selects `data.csv` or `data.jsonl` from the declared format; it does not assume a fixed data member. It validates every manifest member length and SHA-256, data/schema column order, declared logical types and shapes, stable patient or structured row identity, literal values against Builder Preview and the unfiltered Viewer query, publication generation and schema digest, output/revision identity, complete-population scope, and available source/contributor metadata. It also checks that the download modal shows the same representation, generation, schema digest, output types, and full-population scope.

`AUTO` may select JSONL for repeated or structured output. In that case, native JSON values and the exported `rowId` remain intact; an implementation must not manufacture a `data.csv` expectation. CSV inspection retains the distinction between the unquoted null marker, an empty string, and a quoted literal null marker.

The four offline helper tests cover CSV packages, JSONL packages, stale publication/modal identity, and deterministic identity/data mismatches. They do not replace the live journey. The live-only risk is whether the current local Compose stack and browser expose the documented labels, artifact endpoint, and publication metadata exactly as expected; no Docker or Chrome run is part of offline verification.
