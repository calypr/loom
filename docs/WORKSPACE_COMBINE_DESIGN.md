# Combine current draft tables

Implementation design; runtime support and browser acceptance remain unproven.

Users must be able to join or append two current draft tables, including grouped tables, without publishing them first. Published versions remain valid inputs. Automatic preview, Cancel, Apply, edit, removal, and reload must preserve exact source membership and authorization.

Use a closed `WORKSPACE_OUTPUT` input reference containing only a stable sibling output ID. `CompileWorkspace` already includes every document output in one resolved recipe bundle. Its immutable compilation receipt content-addresses that bundle and its generation, authorization, schema, and resolved population inputs. Reuse that snapshot rather than adding separate source-receipt storage or copying recipes into each input.

The reference denotes a dependency within the workspace being compiled. Each new receipt snapshots the complete dependency graph. An upstream edit produces a new bundle and dependent results; it must not silently retain an older source receipt. Destination draft version/digest checks bracket acceptance. Cross-Explorer draft inputs require additional atomic source checks and are a separate remaining requirement.

Recipe/compiler ownership: validate unique output identities, missing references, self references and cycles across the bundle; resolve source schemas from actual compiled outputs; compile dependencies in topological order. Names of local stages are insufficient identifiers because different tables may use the same stage names. Never trust client-supplied source schemas.

Execution ownership: stream complete source outputs, capture each into a distinct leased private ClickHouse artifact, and retain every lease until the final Combine finishes. Apply preview limits only to the terminal output. Memoize shared ancestors and support nested dependencies through the validated graph. Release all acquired artifacts on success, cancellation and partial failure. No publication pointer may change. Production artifact catalog/manager wiring remains a prerequisite.

Authorization ownership: a grouped row cannot truthfully carry one representative resource path. Group captures need explicit whole-relation scope evidence tied to project, generation, exact canonical authorization scope, receipt, output, plan and schema. The compiler must prove every contributing scan/traversal is guarded. Consumption must reauthorize the same full scope and reject scope narrowing; filtering an already aggregated row cannot recover a narrower authorized result. Existing row-path semantics remain in force for row-scoped published inputs. Do not remove the current group guard before equivalent evidence and executable negative tests exist.

Acceptance requires native two-draft join and append lifecycles, grouped sources, duplicate/unmatched keys, schema alignment and nullable padding, nested dependencies, upstream edits and removal, exact independent source values, reload, five-second action-to-render timing, and project/generation/membership/scope isolation. Backend tests must additionally prove cycle rejection, scope narrowing rejection, source identity collision isolation, full-source capture before limiting, and cleanup after a later source fails. Intermediate published-input or contract-only changes do not satisfy this feature.

Alternative considered: separately retained source compilation receipts. That reuses immutable lookup machinery but introduces capture APIs, source receipt retention and version-vector coordination that the existing whole-workspace bundle avoids for same-workspace inputs. Private execution captures are needed under either design.

Scope audit follow-up: `ValidateGenericPhysicalPlanScope` currently validates outer operations and population resource operations. It does not prove guards inside stage-owned `RelatedExpand.RelatedRecords`; CohortGroup uses a separate typed member-resource query. Lowering emits guards, but whole-output evidence needs executable proof for these paths, including removed/misbound/reordered guards. Current validation is insufficient by itself to authorize grouped private captures.

Capture review follow-up: bind stable output ID separately from compiled final stage ID in every artifact identity and comparison. Siblings may share stage names and equivalent plans/schemas. The capture coordinator must accept one distinct source when the planner deduplicates inputs, protect earlier leases while later sources stream, check leases after consumption, and clean up with uncancelled contexts on every exit.

Execution implementation contracts: selected-output compilation retains the complete upstream dependency closure internally while public outputs remain selected/authored. Each upstream capture reads its entire relation; only the terminal result is preview-limited. Nested Combine streams retain their nested leases until their consumers finish. Group/Pivot captures require compiler-issued opaque whole-relation evidence bound to project, generation, complete authorization scope, output, plan and finalized schema. No representative authorization path is invented for aggregate rows. Sealed inputs use identical complete scopes; they cannot be reused under a narrower scope. Ordinary row-scoped artifacts retain their existing path checks. Production manifest conditional updates and removal must enforce revision CAS; cleanup-pending is terminal for active progress updates.
